# LLM Prompt 使用技巧梳理（模板）

> 目的：帮助在不同场景下稳定产出高质量回答，并方便后续复用与迭代。

## 1. 核心原则（优先级从高到低）
1. **明确目标**：先说明你想要的结果形式与用途（如：总结/方案/代码/计划/表格）。
2. **提供上下文**：给出关键背景、约束、已有结论或资料来源。
3. **约束输出**：限定语言、格式、长度、结构与风格。
4. **设定评判标准**：告诉模型你如何判断“好”（如：可执行、可验证、有引用）。
5. **分步引导**：复杂任务拆成清晰步骤，逐步完成。

## 2. Prompt 结构模板
可按以下结构组织：

```
【角色】你是……
【任务】需要你完成……
【背景】相关上下文……
【约束】输出格式/长度/风格/禁用项……
【评判标准】我会按……评估结果
【补充】示例/参考/边界条件
```

> 提示：结构不是强制，但“任务 + 约束 + 背景”通常是最小可行组合。

## 3. 常用技巧清单
### 3.1 任务拆解
- 先要**大纲**，再要**细节**。
- 先要**方案**，再要**执行清单**。

### 3.2 输出可控
- 指定格式：`Markdown`、`JSON`、`表格`、`代码块`。
- 指定字数：如“控制在 300 字以内”。
- 指定风格：如“简洁、要点化、适合分享”。

### 3.3 约束与边界
- 明确“不要做什么”：如“不要推测、不要编造数据”。
- 限定参考来源：如“仅使用下列内容回答”。

### 3.4 逐步校验
- 要求模型先**复述需求**再输出。
- 要求模型列出**不确定点**。

### 3.5 针对不同任务的提示语
- **总结**：请按「一句话结论 + 3 条要点 + 1 条行动建议」输出。
- **方案**：请按「目标/步骤/风险/资源」结构输出。
- **对比**：请用表格对比，并给出推荐建议与理由。
- **代码**：请给出可运行代码，并说明关键步骤。

## 4. 示例（可复制）
### 4.1 知识总结
```
你是知识整理助手。
请把下文总结为：一句话结论 + 3 条关键要点 + 1 条行动建议。
输出为 Markdown，无需额外解释。
内容：<粘贴原文>
```

### 4.2 需求分析
```
你是产品经理。
请根据以下描述提出需求分析与验收标准。
要求：表格形式，包含「需求点/用户价值/验收标准」。
背景：<描述>
```

### 4.3 代码生成
```
你是资深工程师。
请用 Python 写一个脚本完成以下功能：<功能描述>。
要求：
- 可直接运行
- 用函数封装
- 给出简短使用说明
```

## 5. Prompt 复用与迭代建议
- **保留“版本号”**：方便迭代比较。
- **记录效果**：加上“本次效果/问题/改进点”。
- **建立模板库**：按“任务类型/场景/输出格式”分组。

## 6. 常见问题（FAQ）
- **输出太泛**：增加背景信息与具体问题。
- **输出不一致**：提升约束密度与明确格式。
- **输出不完整**：使用分步指令或列检查清单。

## 7. 日常对话中激发能力的 Prompt 片段
> 适用于日常问答、讨论与共创场景，可按需组合或嵌入。

### 7.1 深度思考与结构化
- 请先用一句话概括你的结论，再给出 3-5 个要点支撑。
- 先给出思路框架（步骤/要点），确认后再展开细节。
- 请用“问题-原因-建议”的结构回答。

### 7.2 事实核对与不确定性
- 如果有不确定的部分，请明确标注，并给出你需要的补充信息。
- 只使用已知信息回答，不要推测或编造。
- 如果问题超出已知范围，请直接说明。

### 7.3 多角度思考
- 从用户、业务、技术三种视角分别给出建议。
- 给出 2-3 种可选方案，并说明各自优缺点。
- 先提出反例或潜在风险，再给出结论。

### 7.4 可执行与落地
- 用“下一步行动清单”的方式给出建议。
- 如果需要执行，请给出一个最小可行版本（MVP）方案。
- 给出时间/资源/依赖的简要说明。

### 7.5 交流风格与表达
- 请用简洁、条理化的方式回答，避免长段落。
- 先给结论，再补充理由。
- 如需对外沟通，请用适合转发的口吻。
