## 方法 / 框架
1. **接缝引入法**：逻辑成立于建立可测试边界以降低改动风险。失效条件是代码高度耦合且无法找到可替换点。
2. **保护性测试策略**：逻辑成立于测试锁定行为后才能安全修改。失效条件是行为不可观察或测试成本过高。
3. **增量替换策略**：逻辑成立于降低重写风险与逐步验证。失效条件是系统架构过于耦合导致替换成本极高。

## 反驳与局限
1. **时代局限**：现代测试框架与依赖注入工具降低了部分困难，但并未消除遗留系统的结构性问题。
2. **规模假设**：作者假设团队有时间与资源建立测试，但在高压交付环境下常被忽视。
3. **被后续实践挑战**：部分系统因架构过于老旧导致接缝难以引入，实践中仍需局部重写或拆解。

## 跨书对比（与《Refactoring（重构）》）
《修改代码的艺术》强调在缺乏测试的遗留系统中安全修改，《重构》强调在测试保障下的结构改进。冲突点在于：前者以“建立测试”为首要任务，后者默认测试已存在。适用场景差异是：遗留系统优先应用本书方法；测试完善的系统可直接采用重构手法。
