# 软件工程读书笔记索引

## 系统性知识地图（工程与软件）
软件工程的系统性知识可以分为“工程实践、架构与数据、交付与运营、组织与人”四个层面。工程实践层关注代码质量、可维护性与技术债，强调重构、编码规范、测试与持续演进，这是软件长期可持续性的基础。架构与数据层关注系统在规模化与复杂性增长时的结构性设计，包括分层、模块化、数据一致性、可靠性与可扩展性等核心权衡，决定了系统的性能上限与演进成本。交付与运营层强调从开发到上线的端到端流程，包括持续交付、变更管理、可靠性工程与事故响应，目标是缩短反馈周期并降低生产风险。组织与人层面关注团队协作、项目管理、流程设计与文化建设，涉及沟通机制、权责设计与系统性学习。四层之间存在因果链：高质量工程实践支撑可靠架构，可靠架构支撑稳定交付与运维，稳定交付反过来提升组织学习与协作效率。真正的工程能力不是单点技术，而是跨层协同与约束管理。

## 为什么选择这 10 本书（互补逻辑）
这 10 本书覆盖了从编码到组织的完整路径。《Clean Code》《Refactoring》《Working Effectively with Legacy Code》提供代码质量与演进策略；《The Pragmatic Programmer》补齐工程心智与实践习惯；《Domain-Driven Design》与《Designing Data-Intensive Applications》提供复杂系统建模与数据架构能力；《Accelerate》与《Site Reliability Engineering》覆盖交付与可靠性工程的度量与实践；《The Mythical Man-Month》提供组织与沟通的经典教训；《The Phoenix Project》将DevOps与组织协同以故事形式整合。它们在视角上互补：有的强调微观代码质量，有的强调宏观架构与交付，有的强调组织与文化，从而形成“技术—流程—组织”闭环。

## 推荐阅读顺序 + 原因
1. 《The Pragmatic Programmer（程序员修炼之道）》：建立工程思维与职业习惯。
2. 《Clean Code（代码整洁之道）》：形成代码质量与可读性的基本标准。
3. 《Refactoring（重构）》：理解在保持功能的前提下演进设计的方法。
4. 《Working Effectively with Legacy Code（修改代码的艺术）》：掌握在高技术债环境中安全改动的策略。
5. 《Domain-Driven Design（领域驱动设计）》：建立复杂业务建模与边界设计能力。
6. 《Designing Data-Intensive Applications（数据密集型应用系统设计）》：理解数据系统的核心权衡。
7. 《Accelerate（加速）》：建立交付能力与绩效度量体系。
8. 《Site Reliability Engineering（SRE：站点可靠性工程）》：构建可靠性治理与运维机制。
9. 《The Phoenix Project（凤凰项目）》：以系统视角理解DevOps与协作。
10. 《The Mythical Man-Month（人月神话）》：反思项目管理与沟通的结构性问题。
