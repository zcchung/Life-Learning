# 工程与软件读书笔记知识地图与阅读顺序

## 系统知识地图
工程与软件的系统知识可按“构建—演进—交付—运行”展开：

1. **工程实践与代码质量**
   - 代码可读性、可维护性、重构与技术债。
   - 设计原则与工匠精神。
2. **架构与系统设计**
   - 数据一致性、可靠性、可扩展性与性能权衡。
   - 领域建模与边界划分。
3. **交付与协作机制**
   - 团队协作、流程、约束与效率。
   - 敏捷、精益与DevOps的组织协同。
4. **系统演进与遗留系统治理**
   - 在已有约束下持续演进与降风险。
   - 设计与重构策略。
5. **运行与可靠性**
   - 生产环境稳定性、可观测性与运营。
   - 可靠性工程化与SLO。

## 推荐阅读顺序（含理由）
1. **《The Pragmatic Programmer》**：建立工程师的基本素养与实践态度，是后续方法论的“元能力”。
2. **《Clean Code》**：在日常编码层面建立可读性与可维护性的标准。
3. **《Refactoring》**：将“保持系统可进化”从口号变为具体手段。
4. **《Working Effectively with Legacy Code》**：多数组织面对遗留系统，需掌握现实条件下的演进策略。
5. **《Domain-Driven Design》**：在复杂业务中建立稳健的模型与边界。
6. **《Designing Data-Intensive Applications》**：在数据与规模复杂度提升时理解核心系统权衡。
7. **《The Mythical Man-Month》**：理解项目管理中的结构性失败原因，避免简单人力扩张。
8. **《The Phoenix Project》**：以故事形式理解DevOps协作与瓶颈理论。
9. **《Accelerate》**：用实证研究将DevOps效能与组织实践关联起来。
10. **《Site Reliability Engineering》**：最终进入运行可靠性层面的系统化实践。
